🔐 Security & Access Control Boundary (Updated)

Federated SAML / OIDC can be used for identity federation, but application sessions now use secure httpOnly JWT cookies instead of exposing tokens to JavaScript. Backend enforces Role-Based Access Control (RBAC) on every protected route via middleware. UI gating is performed in the frontend but backend checks remain authoritative.

  • Access token: short-lived JWT stored as httpOnly cookie access_token.
  • Refresh token: longer-lived JWT stored as httpOnly cookie refresh_token; server keeps a revocation identifier (JTI) in an in-memory store for development.
  • Endpoints: POST /api/auth/login, POST /api/auth/refresh, POST /api/auth/logout.

🛠️ Admin Provisioning & Secrets

Default/hard-coded admin passwords were removed from the repository. Automated seeding/reset will only run if DEFAULT_ADMIN_PASSWORD is explicitly supplied in the environment (not recommended for production).

Use the interactive helper backend/setAdminPassword.mjs to create or reset the admin securely (prompts, or --random to generate and print once).

🌐 CORS, Cookies & Environment

Backend sets CORS to only allow the configured frontend origin and permits credentials:

app.use(cors({ origin: FRONTEND_ORIGIN, credentials: true }))

Development backend/.env contains FRONTEND_ORIGIN=http://localhost:5173. For production, also set JWT_SECRET and enable Secure cookie flags with app.set('trust proxy', 1) as appropriate.

🎨 UI changes & Theming

Recent UI updates include removal of the left "New Feedback" action, replacement of the bottom lock control with a Logout button (icon + text), and light-mode text colors adjusted to slate-grey (#374151) to replace pure-black elements. See frontend/src/index.css.
